# Codex 分阶段实施任务

> 配套规范：`01_SPEC.md`；验收用例：`03_ACCEPTANCE.md`。  
> 本文划分实施顺序，不把“后面阶段”自动降为可选。完整 V1 的发布条件是 M0–M8 全部完成。

## 交付规则

每一阶段必须提交真实代码、自动化测试、使用说明及需求追踪更新。目录建议直接采用主规格第 15 节；详细 OpenAPI 与 SQL 迁移在 M0/M1 落地，不能只保留本文中的概念表。

建议提交粒度是一个可验收任务，而不是一次生成整个系统。每次执行 Codex 前说明目标阶段和读入上下文；长任务结束前将结果写入 `docs/IMPLEMENTATION_STATUS.md`，以便后续会话接续。

## M0：契约、脚手架与测试基座

关联：全部需求；重点主规格 5、15、16、17 节。

任务：建立 Rust Cargo workspace / React + TypeScript 工程、Makefile、代码规范和 CI；锁定受支持依赖；创建完整 OpenAPI 及生成的 TS 类型；把 Profile、Source、Report、QuerySpec、JobState、错误码做成共享契约；建立 control/index/report 三类迁移；制作隔离的文件系统夹具生成器。

测试基座至少具备临时根目录守卫、UTF-8/异常文件名、硬链接、符号链接和稀疏文件支持；危险测试根必须是新建临时目录，不能接受环境变量指定的真实共享路径。

Rust/React 专项：落实主规格 15.1–15.10 与 `04_STACK_DECISION.md`，固定 rust-toolchain.toml、Cargo.lock、pnpm-lock.yaml；Axum 路由、SQLite 专用线程与有界消息骨架可执行；完成 React 路由/查询/错误边界；严格验证 config_version=2。

完成标准：主规格 15.10 的适用命令真实通过，schema/API 校验通过；样例数据可生成和自动清理；空实现的测试目标不能返回成功；README 明确还未具备真实扫描。M0 不得把 Go 工程生成后包一层 Rust CLI 当作迁移。

推荐提交：`chore: bootstrap contracts and safe test harness`。

## M1：部署边界、认证与源登记

关联：F04、F05、F13、F16、F18。

任务：配置解析和严格校验；非 root 单容器；默认管理员和首次改密；会话、CSRF、登录限速；部署批准根和 Source CRUD；源只读诊断；Volume 登记/身份确认；目录选择必须根内且 no-follow；CLI config-check、healthcheck。

完成标准：空数据目录可用 `admin/admin` 登录并完成首次改密；已有实例账号不被迁移重置；越界目录访问拒绝；源离线不使整个应用无法登录；只读模式写 API 403；源数据未发生修改；Compose 的配置展开结果与实际挂载一致。

必须先完成 fssecure 读取边界再开始扫描，而不是先使用 std::fs::File::open 任意路径，最后补安全。

## M2：流式扫描、索引与完整性

关联：F06、F07 基础属主、F08、F10、F18。

任务：有界 readdir/目录队列；普通文件元数据；原始路径字节存储；挂载边界；包括/排除规则；身份与硬链接计数；批事务写明细；错误分类和 PARTIAL；worker 隔离与进度；取消/暂停；中断后的重新扫描。

完成标准：黄金夹具的文件数/字节/分类/属主准确；百万级目录不一次加载；权限错误和消失文件不被吞掉；特殊文件不阻塞读取；被排除子树不被误计；不主动修改 atime/mtime/权限。

Rust 专项：专用扫描线程 + 字节/条目双有界管线；持久 frontier 防目录队列膨胀/死锁；取消不得依赖 abort 已启动的阻塞任务；同步 SQLite 不占用 Tokio 核心线程。覆盖 ACC-070 至 ACC-073、ACC-076。

性能任务：先记录 10 万条目峰值 RSS 和索引体积，再做 100 万条目。未达到内存目标时先修扫描模型，不能只增大容器内存绕过目标。

## M3：聚合、目录浏览与不可变报告

关联：F01 基础采样、F06、F07、F08、F10、F11、F12 基础导出、F19。

任务：目录后序聚合、用户/类别汇总、三个排行；容量口径；报告 manifest 和原子发布；摘要与全量明细分离；历史切换/时间轴；分页过滤；源/规则快照；报告对比；CSV/HTML/ZIP 导出与下载授权。

完成标准：首次真实扫描在 Web 显示全部基础栏目；文件数/分类/用户合计一致；CSV 与 UI 查询一致；历史报告不会随规则改变；明细过期时固定排行仍可查看；权限不足范围不被对比成批量删除；静态报告安全转义。

React 专项：服务端分页、十进制字符串无损、StrictMode/重进路由/SSE 清理和慢下载背压覆盖 ACC-074、ACC-075；不得引入额外 Node 运行时。

此阶段可以交付只读演示版本，但不是完整 V1。

## M4：重复文件与读取预算

关联：F09、F17。

任务：size 桶、硬链接折叠、抽样指纹、全量 SHA-256；名称/mtime 附加约束；有界 I/O；验证前后 fstat；缓存信任与失效；独立计算预算和报告列表上限；跨源重复组；protected/tiered 源策略。

完成标准：同大小不同内容不得进入确认组；相同头尾但中间不同不能误判；同 inode 路径不产生节省量；变化文件不能确认重复；超过列表上限有真实截断信息；预算耗尽标明 partial；metadata_only 源没有内容读取。

此时清理 UI 只能显示未启用状态，不得调用直接 unlink 作为临时实现。

## M5：计划、容量历史、通知与导入适配

关联：F01 完整、F02、F03、F04、F07 配额、F14 配置级。

任务：Profile CRUD/复制/版本；持久调度、幂等触发、overlap/misfire/DST；独立容量采样；历史降采样；邮件配置、测试与 outbox；身份/配额 JSON preview/apply；人工预算/真实配额区分；配置导出与恢复预览。

完成标准：应用重启后计划不丢失、不追赶运行上百次；SSE 断线不影响任务；DST 与月末测试通过；邮件真实发送到测试 SMTP；投递失败不破坏报告；导入范围不匹配时不显示虚假比例；导入文件无法扩张部署根白名单。

## M6：安全整理与恢复

关联：F15；主规格 13、14 节的全部阻断要求。

任务：部署/源双开关；内核安全能力检测；危险操作近期再认证；计划预览/过期/幂等；保留副本；完整内容重新比较；受控同文件系统 quarantine；崩溃一致动作日志；恢复冲突；单项及批量操作结果；显式永久清理和保留策略。

实施顺序必须是：fssecure 写操作反例测试 → dry-run 计划 → 隔离 → 恢复 → 崩溃恢复 → purge。不得反过来先提供永久删除按钮。

完成标准：ACC-033 至 ACC-044 及相关攻击用例全部通过；测试只在临时根；候选路径被替换/内容变化时不会删错；不存在剩余副本时拒绝；恢复不覆盖新文件；隔离不会被标成已释放；只读部署没有写入源数据。

M6 必须单独做代码审查记录，指出仍受外部写入影响的风险，不允许“绝对安全”表述。

## M7：容量控制、备份、故障恢复与界面打磨

关联：F11 保留、F12 外部输出、F14 完整、F18。

任务：摘要/明细保留、pin、导出租约、缓存预算；ENOSPC 处理；发布重启恢复；安全配置/完整备份与离线恢复；迁移与回滚；多管理员管理；诊断包与审计；中文可访问性与长文件名显示。

完成标准：ENOSPC 不发布假成功；正在下载的报告不被回收；ZIP slip/超大包/符号链接导入被拒绝；迁移失败可恢复到备份；诊断不含秘密；删除 Profile 不删除源文件；任务列表所有按钮与后端行为一致。

## M8：发布验证与绿联部署验收

关联：F01–F19 全量追踪。

任务：双架构镜像和 SBOM/依赖清单；amd64/arm64 冒烟；真实 NAS 小目录验证；Compose/UGOS Project 使用说明；明确 UID/GID/ACL 设置；性能与稳定性报告；升级/回滚演练；完整闭环演示。

Rust 发布专项：按 ACC-069、ACC-077 验证锁定工具链、release 构建、C/SQLite 与目标架构一致、镜像不需要编译器或 Node。Rust/React 专项 ACC-069–ACC-078 全部纳入需求追踪，不取代原 68 条验收。

完成标准：每条 Fxx 对应实现、自动测试和必要的实机证据；明确自动系统配额、Tiering 等环境适配状态。没有用户真实设备时，实机项标记“未验证”，不能伪造通过；其余可在本地 Linux/CI 完成的项不能因此停止。

完整发布包必须包含：源代码、精确锁文件、完整 API 文档、数据库迁移、Docker 构建/部署文件、操作文档、测试结果、基准数据和已知限制。
