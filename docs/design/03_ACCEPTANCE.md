# 验收标准与自动化测试设计

> 关联主规格 `01_SPEC.md`。以下是必须实现并执行的测试，不是已经运行过的应用测试结果。

## 1. 测试层次和证据

单元测试覆盖规则、口径、状态机和错误码；集成测试使用真实临时目录、SQLite 与测试 SMTP；端到端测试验证浏览器操作；安全测试覆盖恶意路径与竞争条件；性能测试记录指定数据集与硬件；最后以绿联 NAS 独立测试共享目录验证真实挂载权限。

任何危险测试只允许在测试进程新建并持有标记的临时目录中执行。夹具生成器必须拒绝非空目录、符号链接根、宿主机 `/` 和用户任意已有目录；清理测试不接收生产 SOURCE_PATH。测试结束前核验 fixture 外的 KEEP 文件完全未改变。

测试报告必须给出命令、时间、版本、架构、输入规模与通过/失败/未执行状态。不允许把本文检查列表复制为“全部通过”。

## 2. 基础黄金数据集

在临时根下创建两个登记源 alpha 和 beta。以下八个普通文件构成基础数据集；其他稀疏、符号链接和竞争夹具单独创建，避免污染确定性合计。

| 路径 | 内容 | 逻辑大小 | 备注 |
| --- | --- | --- | --- |
| alpha/docs/readme.txt | ASCII `hello` 加 LF | 6 | 第一个物理对象 |
| alpha/docs/copy.txt | ASCII `hello` 加 LF | 6 | 独立复制 |
| alpha/docs/hard.txt | readme.txt 的硬链接 | 6 | 同一物理对象，不是额外内容副本 |
| alpha/media/movie.bin | ASCII B 重复 17 次 | 17 | 按默认 bin 归 disk_images，不按文件名猜视频 |
| alpha/empty.dat | 空内容 | 0 | other |
| alpha/名称,<LF>换行.txt | ASCII `xyz` | 3 | 文件名含逗号和真正的换行 |
| beta/copy.txt | ASCII `hello` 加 LF | 6 | 第三个独立内容副本 |
| beta/changed.txt | ASCII `HELLO` 加 LF | 6 | 相同长度但内容不同 |

期望：普通路径 8 个；可靠身份去重后 7 个对象；条目逻辑总量 50 字节；唯一逻辑总量 44 字节；alpha 38、beta 12；documents 33 字节、disk_images 17 字节、other 0 字节。文件数量中 other 仍包含空文件，不能因 0 字节被忽略。

重复内容 `hello<LF>` 有 3 个独立对象、4 个路径别名，逻辑冗余 12 字节。hard.txt 不能额外增加冗余量。已分配块数取实际文件系统值校验，不对所有平台硬编码成 4 KiB。

### D. 安全整理——M6 发布阻断案例

| 编号 | 输入/操作 | 通过标准 |
| --- | --- | --- |
| ACC-033 | 分别关闭部署开关/源开关/写挂载；缺少内核安全能力 | 任一条件不足都拒绝写入；不通过 fallback 降低写安全标准 |
| ACC-034 | 选择一个组全部副本；伪造不属于报告/组的 entry_id | 拒绝；至少有一个验证有效的保留副本；不能注入任意文件 |
| ACC-035 | 过期计划、修改计划参数、无再认证、重复提交 | 过期/篡改拒绝；双击只有一个 action；会话认证不能代替近期再认证 |

| ACC-041 | 在写日志前后、rename 前后、状态提交前后强制退出 | 重启核对双方路径与身份；不重复移动、不丢文件、不误报成功 |

| ACC-044 | 未确认的批量 purge、自动策略默认值、隔离期未到 | 默认不自动永久删；再认证和明确确认有效；定期策略遵守最短保留 |

## 4. 端到端脚本最少动作

使用 Playwright 或等价工具完成：初始化 → 登录 → 登记两个测试源 → 导入身份/配额 → 创建并运行报告 → 检查黄金合计 → 打开目录/用户/类别/重复/排行 → 下载 CSV → 修改分类再运行 → 检查历史未变 → 配置测试 SMTP → 导出备份 → 在隔离测试实例恢复。

可写 E2E 单独运行，并明确传入测试开关：生成重复组 → 预览 → 重新认证 → 隔离 → 确认源文件状态 → 恢复 → 再隔离 → 确认保留副本 → purge。默认 CI 不接触任何生产挂载。

## 5. 基准报告模板

记录 CPU 型号/核心、内存、存储介质、文件系统/挂载选项、内核、容器限制、数据集文件与目录数、总逻辑大小、路径长度分布、重复率、warm/cold cache、扫描开关、并发、限速、应用版本。

输出总耗时、entries/s、哈希读取量与吞吐、总峰值 RSS、索引/摘要/WAL 峰值体积、查询 p50/p95/p99、错误率、取消反馈耗时。运行至少三轮并说明波动，不能只报告最快一次。

## 6. 最终验收表

实现者另行创建 `docs/ACCEPTANCE_RESULTS.md`，每个 ACC 编号必须有状态、测试命令/测试文件、结果证据与备注。平台依赖项可以 UNVERIFIED，但不能改为 PASS；所有可自动验证的安全阻断项必须 PASS 才允许打开写操作发布。
